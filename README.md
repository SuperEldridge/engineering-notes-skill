# 工程笔记Skill

这是一个用于编写、改写、归纳或审查可复用工程技术笔记的指令（Skill）。适用于控制算法、嵌入式系统、电机、电子、电气、机械、测试与参数辨识等领域。

该指令旨在生成独立、简洁且可落地的工程笔记，帮助读者快速掌握结论与实现路径，并明确公式前提、数据链路、边界条件及验收方式。

## 🎯 核心目标

将离散的材料、测试记录或对话归纳为一份标准的工程笔记载体。保留对工程决策有用的理论推导、约束和检查点，同时坚决剥离仅服务于当前项目的偶然细节与代码实现。

## 🚀 核心原则与边界

- **完全解耦代码**：禁止在正文中包含具体文件路径、源码片段、变量名、宏定义或寄存器级操作。所有底层实现均需抽象为通用的数据与控制链路。
- **理论依据充实**：提供从物理模型到目标参数的最短充分推导。必须说明公式中变量的物理含义、单位约定（如峰值/RMS、线/相电压）以及成立条件。
- **高度聚焦，不发散**：不引入无关的行业背景、替代方案或泛泛而谈的建议。不把验证内容扩展为冗长的测试计划，仅保留影响结论可信度的关键筛选和验收点。
- **规范的量纲管理**：严格区分“原始测量量”“坐标变换控制量”与“最终估计量”，确保系数与单位在物理意义上完全对齐。

## 📝 标准化输出结构

通过此 Skill 生成的工程笔记将遵循以下层次结构（根据主题动态裁剪不适用小节）：

1. **结论**：说明解决的核心问题、产出判据、适用范围与不包含的内容。
2. **理论依据**：从贴近目标的模型开始推导，明确变换约定与关键前提。
3. **初值或量级校验**：铭牌数据、经验值或数据表校验基准。
4. **需要的观测量**：以表格形式列出物理量、用途、要求或来源。
5. **实施流程**：按“准备 → 激励/工况 → 稳态采样 → 单点诊断 → 全局估计 → 输出”描述最小闭环。
6. **数据筛选与验收**：无效数据的判定条件、拟合策略、交叉检查及通过标准。
7. **结果记录**：列出需长期保存的参数、单位、工况及筛选策略。
